# ToolRise ChatMod

Клиентский мод модерации чата для **Minecraft 1.21.11 / Fabric**.

Сообщения с нарушением подсвечиваются в чате **красным**, при наведении показывается,
какое правило сработало и какой мут положен, а по **клику** выдаётся мут.

Правила взяты с https://toolrise.space/rules (раздел 2.x — всё, что карается мутом),
списки слов и исключений — из таблицы
[«ToolRise | таблица исключений и нарушений»](https://docs.google.com/spreadsheets/d/1mrJSc2SySzo2iSeE90aPLZOFBNyyxFxuQYiOSrUeEvc/edit?gid=458816284)
(лист `TL`).

---

## Что умеет

| | |
|---|---|
| Подсветка | нарушение красится красным, перед ним метка `[! 2.1]` |
| Подсказка | наведение курсора показывает правило, срок мута и что именно сработало |
| Клик | ЛКМ — окно выдачи мута, Ctrl+ЛКМ — выдать сразу, Shift+ЛКМ — вставить ник в поле ввода |
| Обход фильтра | ловит `х.у.й`, `х у й`, `хууууй`, `cyka`, `пидoрас` (латинская o), `shalava`, `suka`, `н0вый` |
| Исключения | фразы из блока «ИСКЛЮЧЕНИЯ» таблицы не считаются нарушением |
| Пауза | автомат ждёт, чтобы модератор успел выдать наказание сам |
| Ранги | состав не проверяется, медийным потолок мута 10 минут |
| Игнор | конкретного игрока можно убрать из проверки одним кликом |
| Чужие ники | `Dj_pIdOrAs бекни` — не нарушение: за ник отвечает его владелец по 3.7 |
| Журнал | каждое выданное наказание пишется в `punishments.csv` — удобно для подсчёта нормы |
| Протокол | на каждый мут сохраняется доказательство в папке игры, `trmod/` |

Мод **ничего не отправляет на сервер сам**. Проверка идёт локально, команда мута
уходит только после явного действия модератора.

## Установка

1. Minecraft **1.21.11**, [Fabric Loader](https://fabricmc.net/use/installer) **0.19.3+**
2. [Fabric API](https://modrinth.com/mod/fabric-api) **0.141.5+1.21.11**
3. Положить `toolrise-chatmod-1.0.0.jar` в папку `mods`

Готовый файл: `build/libs/toolrise-chatmod-1.0.0.jar`.

### Сборка из исходников

```bash
./gradlew build
```

## Первый запуск: проверьте команду мута

При первом старте создаётся папка `config/trchatmod/` с двумя файлами.
По умолчанию команда собирается под формат ToolRise — `/mute игрок 4h 2.4`:

```json
"muteCommand":   "mute {player} {time} {reason}",
"reasonTemplate": "{ruleId}",
"permanentToken": "perm"
```

`permanentToken` — единственное, что не проверено: подставьте то, что ваш плагин
принимает за вечный мут (`perm`, `permanent`, `0`…).

Проверить, как мод разбирает чат вашего сервера, можно командой:

```
/trchatmod test ты тварь
```

Если ник в окне выдачи мута определяется неправильно — поправьте `chatPatterns`
(см. ниже).

## Автомат: нажал кнопку и ушёл

**F8** — включить/выключить автоматическую выдачу мутов. Пока автомат включён,
в правом верхнем углу горит индикатор `● АВТОМАТ` со счётчиками — забыть, что он
работает, невозможно.

Дальше человек не нужен: каждое нарушение наказывается само. Работает, пока
клиент подключён к серверу, — в том числе когда игра свёрнута и вы занимаетесь
своими делами (Minecraft продолжает тикать в фоне).

### Порядок ввода в бой

1. `/trchatmod auto dry on` — тестовый режим: автомат считает и пишет в чат
   `[ТЕСТ] выдал бы: /mute ...`, но команду **не отправляет**.
2. Посидеть так час-другой в живом чате и посмотреть, не ловит ли лишнего.
3. `/trchatmod auto live` — снять тест и включить автомат по-настоящему.

Тест — залипающее состояние, поэтому пока он включён, при каждом включении
автомата в чат приходит кнопка **[включить по-настоящему]**: один клик и всё
работает. Если видите в чате «АВТОМАТ ВКЛЮЧЁН, НО В ТЕСТОВОМ РЕЖИМЕ» —
команды никуда не уходят.

Шаг 1 можно и пропустить, но ошибка автомата — это невиновный игрок с мутом,
пока вы спите.

### Пауза для людей

У обычных модераторов норма и зарплата считаются по количеству наказаний.
Мгновенный автомат забрал бы всю их работу, поэтому между обнаружением и
выдачей есть пауза — по умолчанию **30 секунд**:

Настраивается прямо в игре, файл править не надо:

```
/trchatmod auto delay 60    — поставить минуту
/trchatmod auto delay 0     — выключить паузу, выдавать сразу
/trchatmod auto delay       — посмотреть текущую
```

В `config.json` это `autoDelaySeconds`.

Что происходит в эти 30 секунд:

```
[Авто] через 30 сек: Player_01 — 2.1 Оскорбления — 30m [отменить]
```

- **успел человек** — автомат молча отходит: `не выдаю Player_01 — модератор выдал вручную`
- **не успел** — команда уходит сама

Чужие наказания ловятся двумя путями: мут через этот же мод снимает отложенную
выдачу сразу, а наказание от другого модератора — по объявлению в чате
(`autoPunishBroadcastPatterns`, ищется строка с ником и словом «замучен»,
«выдал мут» и т.п.).

| Команда | Что делает |
|---|---|
| `/trchatmod pending` | что автомат сейчас держит на паузе и сколько осталось |
| `/trchatmod cancel <id>` | снять конкретную отложенную выдачу |
| `/trchatmod cancel` | снять все |

В индикаторе на экране появляется счётчик `ждёт N`.

Хотите дать модерам больше времени — поставьте 60–120.

### Протокол на каждое наказание

Мут без доказательства оспорят. Поэтому на каждую выдачу — свою и автомата —
сохраняется протокол в **папке игры**, в `trmod/ГГГГ-ММ-ДД/`:

```
19-42-07_player_01_2.1-оскорбления.txt
19-42-07_player_01_2.1-оскорбления.png
```

Окно показа (120 сек) шире окна флуда (60 сек), поэтому засчитанные повторы
помечены `*`: без этого протокол читается как «четыре повтора за две минуты»
и доказывает не то, за что выдан мут.

Внутри текстового файла:

```
ПРОТОКОЛ НАКАЗАНИЯ
время / модератор / нарушитель / правило / срок / причина / источник / команда

СООБЩЕНИЕ-НАРУШЕНИЕ
[17:16:23] G | Без клана | ФАНТОМ Player_04 » тупой ты

ЧТО СРАБОТАЛО
2.1 Оскорбления — мут 30 мин
    тупой

ВСЕ РЕПЛИКИ ИГРОКА ЗА ПОСЛЕДНИЕ 120 СЕК (4)
Флуд считается по окну 60 сек, порог 4. * — попавшее в окно: 3 из 4
  [20:57:02] ... » продам сет      ← показано для контекста, но НЕ засчитано
* [20:58:08] ... » продам сет
* [20:58:28] ... » продам сет
* [20:58:49] ... » продам сет

ЧАТ ВОКРУГ СОБЫТИЯ (40 строк)                   ← строки нарушителя помечены >>
```

**Где именно эта папка** — зависит от лаунчера: это тот же каталог, где лежат
`mods`, `config`, `screenshots` и `logs`. У официального лаунчера это
`%APPDATA%/.minecraft/trmod`, у сборок, TLauncher и Prism — свой путь.

Не искать вручную:

```
/trchatmod proof
```

Команда печатает полный путь и сразу открывает папку в проводнике. После каждого
выданного мута в чате рядом с именем протокола есть кнопка **[открыть папку]**.
Путь также пишется в `logs/latest.log` при запуске игры.

**Про скриншот честно:** он прикладывается, но полагаться на него нельзя.
Чат в игре гаснет через несколько секунд, а автомат выдаёт мут с задержкой —
к моменту снимка нужной строки на экране может уже не быть. Текстовый протокол
собирается из буфера сообщений и от этого не зависит, поэтому доказательство
именно он. Скриншот выключается через `"saveScreenshot": false`.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `saveEvidence` | `true` | сохранять протоколы |
| `evidenceDir` | `trmod` | имя папки внутри каталога игры |
| `evidenceContextLines` | `40` | сколько строк чата вокруг события |
| `evidenceWindowSeconds` | `120` | за сколько секунд собирать реплики нарушителя |
| `saveScreenshot` | `true` | прикладывать снимок экрана |
| `chatLogBufferSize` | `300` | сколько строк чата держать в памяти |

### Игнор конкретных игроков

Когда один человек сидит и нарушает, а разбираться с ним сейчас не хочется —
убираем его из проверки. Три способа, все делают одно и то же:

- **кнопка `[игнор]`** в конце помеченного сообщения — один клик
- **кнопка «Не проверять этого игрока»** в окне выдачи мута
- **команда** с подсказкой ников онлайн:

```
/trchatmod ignore add <ник>      — не проверять
/trchatmod ignore remove <ник>   — вернуть в проверку
/trchatmod ignore list           — кто сейчас в игноре
/trchatmod ignore clear          — очистить список
```

Список сохраняется в `config.json` (`ignoredNicks`) и переживает перезаход.
После добавления в чат приходит кнопка `[вернуть]` — если промахнулись.

Кнопку в чате можно убрать: `"showIgnoreButton": false`.

### Ранги: кого не трогать и кому мягче

Ранг игрока стоит прямо в строке чата перед ником, и мод берёт его оттуда.
Список ников в `rules.json` устаревает при каждой ротации состава — ранг нет.

```
G | Без клана | ORGANIZATOR KBAC1K » текст
                ↑ отсюда
```

**Состав не проверяется вообще** (`staffRanks` в `config.json`):

```
OWNER, DEVELOPER, ORGANIZATOR, MANAGER, CURATOR, GL.CURATOR, ZAM.CURATOR,
ADMIN, ST.ADMIN, MODER, ST.MODER, GL.MODER, HELPER, ST.HELPER
+ русские: ВЛАДЕЛЕЦ, РАЗРАБОТЧИК, УПРАВЛЯЮЩИЙ, КУРАТОР, АДМИН, МОДЕР, ХЕЛПЕР, СЛЕДЯЩИЙ
```

**Донатные ранги в этот список не входят намеренно.** `D.ADMIN`, `D.OWNER`,
`ХОЗЯИН`, `VLASTELIN`, `SHULKER`, `OVERLORD` — покупные, их владельцы
проверяются как обычные игроки. Именно поэтому ранг сравнивается целым словом,
а не куском строки: поиск подстроки «ADMIN» принял бы `D.ADMIN` за
администратора и перестал бы его проверять.

**Медийным мут не больше 10 минут** (`rankMuteLimits`):

```json
"rankMuteLimits": { "YOUTUBE": "10m", "TIKTOK": "10m", "MEDIA": "10m", "БЛОГЕР": "10m", "СМИ": "10m" }
```

Даже за нарушение с 4-часовым мутом такому игроку уйдёт 10 минут — и в окне
выдачи, и у автомата, и по Ctrl+клику. Если рангов несколько, действует
самый мягкий потолок.

Проверить, как разбираются ранги:

```bash
./gradlew -q rules --args="ranks"
```

### Предохранители

| Настройка | По умолчанию | Зачем |
|---|---|---|
| `autoMaxMute` | `4h` | потолок строгости; всё строже уходит в очередь на ручную проверку |
| `autoMaxPerMinute` | `6` | сломанное правило не выкосит весь сервер |
| `autoCooldownSeconds` | `90` | один конфликт не превращается в серию мутов одному игроку |
| `autoRequireOnlineNick` | `true` | не наказывать, если ник не найден среди игроков онлайн |
| `autoSkipRules` | `[]` | номера правил, которые автомат не трогает никогда |
| `autoSkipLinePatterns` | эхо плагина наказаний | иначе автомат зациклится на собственных мутах |

**Потолок `4h` означает, что 2.3 (7 дней) и 2.7 (мут навсегда) автомат сам не
выдаёт** — они попадают в очередь, вы жмёте F9 и решаете сами. Чтобы автомат
выдавал вообще всё, поставьте:

```json
"autoMaxMute": "permanent"
```

### Если ошибся

```
/trchatmod undo      — снять последний автомут
/trchatmod undo 5    — снять пять последних
```

В `punishments.csv` появилась колонка «источник» (`авто` / `вручную`) — видно,
что выдал автомат, а что вы руками.

### Чего автомат не делает

- **Не работает с закрытой игрой.** Клиентский мод физически не может отправить
  команду, когда Minecraft выключен: команда идёт по вашему подключению к серверу.
  Свернуть окно можно, закрыть — нет. Круглосуточная модерация без запущенного
  клиента — это серверный плагин, другая история.
- **Не держит вас от кика за AFK.** Анти-AFK намеренно не добавлен: по пункту 4.0
  ваших же правил такие моды запрещены, и ловить бан от своих коллег из-за
  модераторского инструмента — плохой размен.

### Как понять, что мод работает по свежим правилам

При заходе на сервер мод печатает одну строку:

```
[ChatMod] правила v3 · флуд 4/60с · мат от 6 · автомат выкл [папка]
```

Если цифры не те, что вы ждёте — значит `rules.json` в конфиге старый и мод
читает его, а не свой jar. `[папка]` открывает каталог настроек.

### Обновление правил при выходе новой версии мода

`rules.json` и `config.json` создаются один раз и дальше принадлежат вам —
мод их не перезаписывает, иначе терялись бы ваши правки. Но из-за этого
обновление мода само по себе не меняет уже созданные файлы.

Поэтому у обоих есть версия. Если версия в файле ниже той, что несёт мод:

- **`rules.json`** — старый файл сохраняется рядом как `rules.vN.json.bak`,
  на его место кладётся свежий. В чате и в логе пишется, куда делась копия.

  **При любой правке `default_rules.json` поднимайте `schema` на единицу.**
  Мод не трогает уже созданный `rules.json`, пока схема в нём не ниже — без
  этого правка останется в jar и до игрока не доедет. Это уже приводило к тому,
  что новый порог флуда неделю не работал.
- **`config.json`** — обновляются только те поля, ради которых поднята версия
  (`chatPatterns`, `reasonTemplate`). Остальные ваши настройки не трогаются.

Проверить, что применилось, — `/trchatmod reload`, он печатает отчёт.

### chatPatterns и системные сообщения

Регулярки проверяются по порядку, первая подошедшая выигрывает. Обязательны
именованные группы `nick` и `msg`. Первый шаблон — формат ToolRise:

```
[17:17:38] G | Без клана | VLASTELIN Player_03 » блять почему стоки не падают
                                     ↑ ник      ↑ разделитель ↑ сообщение
```

```json
"^.*?(?<nick>[A-Za-z0-9_]{3,16})\\s*»\\s*(?<msg>.+)$"
```

**`requireKnownSender: true`** — сообщения без распознанного ника не проверяются
вообще. Это отсекает рамки из `═`, объявления про квесты и рекламу кейсов: наказать
за них всё равно некого. Отключать стоит только если шаблоны не настроены и мод
молчит совсем.

Посмотреть, как мод разбирает конкретную строку:

```
/trchatmod parse [17:17:38] G | Без клана | VLASTELIN Player_03 » текст
```

Покажет ник, текст и что по нему сработало. Так же проверяется целый лог:

```bash
./gradlew -q rules --args="scan tools/samplechat.log"
```

В отчёте у каждой строки виден распознанный ник или `<без ника>`.
`tools/samplechat.log` — образец реального чата ToolRise для проверки шаблонов.

## rules.json

Каждое правило — пункт с сайта:

```json
{
  "id": "2.1",
  "name": "Оскорбления",
  "mute": "30m",
  "enabled": true,
  "phrases": ["@insults"]
}
```

`mute`: `10m`, `15m`, `30m`, `1h`, `4h`, `7d`, `permanent`.
Если сработало несколько правил, по умолчанию предлагается **самое строгое**,
остальные доступны кнопками в окне выдачи.

### minMatches — порог срабатываний

`"minMatches": 6` означает, что правило считается нарушенным только при шести
и более **разных** совпадениях в одном сообщении. Так настроено 2.9:

```json
{ "id": "2.9", "name": "Нецензурная лексика", "mute": "15m", "minMatches": 6 }
```

По решению модерации одиночный мат не наказывается — `блять почему стоки не
падают` проходит, а сообщение с шестью матами ловится. Считаются
непересекающиеся участки: если одно слово поймали два паттерна, это одно
нарушение, а не два.

Оскорбления в адрес игрока (2.1) под этот порог не попадают — там хватает
одного совпадения. То есть `иди нахуй` по-прежнему 30 минут, потому что это
оскорбление, а не просто мат.

### Синтаксис фраз

| Запись | Смысл |
|---|---|
| `тварь` | обычная фраза |
| `re:\bт[уy]п(ой\|ая)\b` | регулярное выражение Java |
| `@insults` | подставить всю группу из `groups` |

Обычные фразы нормализуются автоматически: регистр, растянутые буквы, латиница
вместо кириллицы, транслит и разделители внутри слова уже учтены — писать варианты
не нужно.

**Для `re:` есть одно ограничение:** текст перед поиском схлопывает повторяющиеся
буквы (`нигггер` → `нигер`), поэтому в регулярках не пишите удвоенные буквы.

Хвост слова допускается длиной до `settings.suffixTolerance` символов (по умолчанию 2),
поэтому `мразь` ловит и `мразью`.

### Флуд

Определение проекта: **4 и более одинаковых сообщений за минуту**. Задаётся в
`settings`:

```json
"spamRepeatCount": 4,
"spamWindowSeconds": 60,
"spamMinLength": 3
```

Реплики короче `spamMinLength` (3 символа) не считаются: «да», «я», «гг» в живом
разговоре повторяются постоянно и флудом не являются.

Сообщения сравниваются после нормализации, поэтому `кто продаст сет`,
`КТО ПРОДАСТ СЕТ` и `кто продаст сет!!` считаются одинаковыми — менять регистр
и добавлять знаки бесполезно. Наказание — 2.0, мут 10 минут.

Проверить детектор (обычный `verify` его не проверяет — он зависит от истории
сообщений):

```bash
./gradlew -q rules --args="flood"
```

Отдельно от этого есть `FLOOD_RATE` на правиле 2.10 — он ловит быстрый поток
**разных** сообщений (8 за 10 секунд). Это не определение флуда проекта; если
не нужен, поставьте правилу 2.10 `"enabled": false`.

### combos

Срабатывает, только если в сообщении есть что-то из `a` **и** что-то из `b`:

```json
"combos": [ { "a": ["@family"], "b": ["@insults", "@profanity"] } ]
```

Так сделаны правила 2.2 (оскорбление администрации), 2.3 (негатив о сервере)
и часть 2.4 («Мать/Батя (любое оскорбление)» из таблицы).

### detectors

Проверки, которые списком слов не задать:

| Детектор | Что ловит | Где используется |
|---|---|---|
| `CAPS` | доля заглавных ≥ `capsRatio` при длине ≥ `capsMinLength` | 2.0 |
| `REPEAT_CHARS` | `repeatCharThreshold` (8) одинаковых символов подряд | 2.8 |
| `SPAM_REPEAT` | **флуд: 4 и более одинаковых сообщений за минуту** | 2.0 |
| `FLOOD_RATE` | 8 разных сообщений за 10 сек — отдельный детектор, не «флуд» по правилам | 2.10 |
| `AD_THIRD_PARTY` | ссылки, IP:порт, «заходи на…» — кроме `settings.adWhitelist` | 2.7 |
| `AD_OWN_CHANNEL` | YouTube / Twitch / TikTok / Telegram / VK, «подпишись» | 2.5 |

### exceptions

`phrases` — блок «ИСКЛЮЧЕНИЯ» из таблицы (строки 47–59) слово в слово.
Совпадение, **целиком накрытое** исключением, не считается нарушением: поэтому
`конченый` проходит, а `мразь конченый` — нет.

`technicalPhrases` — добавлено самим модом, чтобы гасить ложные срабатывания
морфологии (`чмоки`, `жидкий`, `тупик`, `хутор`…). Это не часть правил проекта,
можно удалить.

## Охота за обходами

Игроки быстро учатся обходить фильтр: `т_в_а_р_ь`, `shalava`, латинская `o`
в середине слова. Чтобы это не превращалось в ручную работу, в проекте есть
две вещи.

### Утилита проверки правил

```bash
./gradlew -q rules --args="verify"                 # прогон корпуса tools/testcases.txt
./gradlew -q rules --args="scan <лог>"             # что проскочило в реальном чате
./gradlew -q rules --args="check <файл>"           # прогон файла: строка = сообщение
./gradlew -q rules --args="test ты тварь"          # один текст
./gradlew -q rules --args="norm ты т_в_а_р_ь"      # почему обход не совпал
```

В консоль печатается только короткая сводка, **полный отчёт — в
`build/rules-report.txt`** (UTF-8; консоль Windows кириллицу коверкает).

`scan` разбирает `logs/latest.log` Minecraft: Minecraft пишет туда каждую строку
чата, а мод помечает нарушения меткой `[!`. Утилита показывает, что правила
**не** поймали — это и есть список кандидатов на обход.

`norm` показывает все девять нормализованных вариантов текста — сразу видно,
на каком шаге обход ушёл:

```
CYRILLIC_HOMOGLYPH  KEEP     -> ты т в а р ь
CYRILLIC_HOMOGLYPH  STRIP    -> ты тварь          <- здесь ловится
CYRILLIC_HOMOGLYPH  SQUEEZE  -> тытварь
```

`tools/testcases.txt` — регрессионный корпус (сейчас 114 случаев: что обязано
ловиться и что обязано проходить). **Любая правка правил проверяется им**,
иначе новая регулярка тихо начнёт банить за слово «хутор».

### Агент bypass-hunter

`.claude/agents/bypass-hunter.md` (лежит в `D:\poganec\`, рядом с папкой мода —
если откроете Claude Code прямо в папке мода, скопируйте файл в
`ToolRiseChatMod/.claude/agents/`).

Агент Claude Code, который делает всё вышеописанное сам:

```
запусти bypass-hunter, проверь логи за сегодня
```

Что он делает:

1. прогоняет `verify` — если корпус уже красный, дальше не идёт;
2. разбирает логи Minecraft (`scan`) и вытаскивает непойманные сообщения;
   если логов нет — сам генерирует обходы для слов из `groups` и проверяет их;
3. по каждому кандидату запускает `norm`, чтобы понять причину;
4. добавляет минимальный паттерн в нужную группу `rules.json`;
5. заводит на каждую правку `FLAG`-случай (реальный текст из чата) и `CLEAN`-случай
   (похожее безобидное слово) в `tools/testcases.txt`;
6. снова `verify` — если стало красным, сужает паттерн или откатывает правку;
7. докладывает, что добавил и с какими доказательствами из чата.

Чего он не делает намеренно: не трогает `exceptions` (это политика проекта,
сужать её может только человек), не меняет сроки мутов и номера правил, не
добавляет ники в `staffNicks`, не коммитит.

## Что стоит знать перед использованием

- **Мод — помощник, а не автомат.** Он подсвечивает и предлагает; решение и
  ответственность остаются на модераторе. Ни одна проверка не выдаёт мут сама.
- **Списки слов для 2.1 и 2.4 — точная копия таблицы**, включая опечатки
  (`Приветь`, `не чуствую`) и спорные позиции в исключениях. Не редактировал:
  это ваша политика, а не моя.
- **Для 2.2, 2.3, 2.5, 2.6, 2.7, 2.9 и попрошайничества в таблице списков нет** —
  они собраны по формулировкам с сайта. Проверьте их на своём чате и правьте.
- **2.3 (7 дней) и 2.7 (мут навсегда) — самые тяжёлые санкции**, а детект у них
  эвристический. Их всегда стоит проверять глазами: окно подтверждения включено
  по умолчанию именно поэтому.
- **`replacePlayerChat: true`** для подписанного ванильного чата отменяет исходное
  сообщение и добавляет своё, уже красное. Побочный эффект — у такого сообщения
  теряется подпись (жалоба на чат по нему работать не будет). Чат серверных
  плагинов приходит как системное сообщение и правится без этого эффекта.
- **Ники администрации** в `groups.staffNicks` взяты из таблицы на момент сборки
  и наверняка устареют — обновляйте.

## Как это работает внутри

```
входящее сообщение
   ├─ ClientReceiveMessageEvents.MODIFY_GAME   (чат плагинов — правится на лету)
   └─ ALLOW_CHAT + CHAT_CANCELED               (подписанный чат — заменяется)
        │
        ├─ ChatParser        ник + тело сообщения по chatPatterns
        ├─ TextNormalizer    6 вариантов: 3 способа сведения букв × 2 режима разделителей
        ├─ RuleEngine        фразы, комбо, детекторы; вычитание исключений
        └─ ChatDecorator     красный цвет + ClickEvent + подсказка
                              │
                              └─ клик → /trchatmod punish <id>  (клиентская команда,
                                        на сервер не уходит)
                                     └─ PunishScreen → PunishmentExecutor → /mute …
```

Миксины не используются — всё держится на публичном API Fabric и ванильных
`ClickEvent` / `HoverEvent`, поэтому мод переживает мелкие обновления игры.
